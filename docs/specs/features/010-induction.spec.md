## 1. 背景

楞次定律是整本高中教材里**空间推理密度最高**的一条规律，也是错误率最高的一处。
学生的普遍状态是：背下来了「增反减同」四个字，做题时凭手感画个顺/逆时针，
换个图（比如从线圈背面看）就全错。

根因在于，用楞次定律判断电流方向要**连续用两次右手定则**：

1. 由磁铁的磁极朝向与运动方向 → 判断穿过线圈的**原磁通**指向哪一侧；
2. 由原磁通是增是减 → 判断**感应电流**该往哪个方向绕。

平面图上这两步都退化成「顺时针 / 逆时针」两个词，中间的因果链完全看不见。
于是它只能被当成口诀来背，而不能被理解。

配套的第二个误区同样顽固：**「磁通量最大时感应电流最大」**。
这是把量和量的变化率混为一谈（和「速度最大时加速度最大」是同一类错误）。

---

## 2. 为什么必须真 3D

`dimension: 3d`。

在 3D 里可以同时立起**三根互不相同、又彼此关联**的矢量：

- 线圈法向 `n̂`（决定「正向」是哪个方向）；
- 原磁场 `B`（粉色，磁铁在线圈中心处产生的场）；
- 感应磁场 `B'`（紫色，由感应电流产生的场）。

「增反减同」比较的是 `B'` 与 `B` 的方向关系，而这个关系只有在
**法向也看得见**的情况下才有意义。转一下视角就能看清：当磁铁靠近时
`B'` 与 `B` 反向；过最近点后 `B'` 翻转，与 `B` 同向。

平面图上这三根矢量要么重叠、要么平行于画面，做不到这一点。

## 3. 用户故事

1. 作为学生，我想看清「原磁场 B」和「感应磁场 B'」是两个独立的箭头，而不是同一个东西。
2. 作为学生，我想看到磁铁靠近时 B' 与 B 反向、远离时同向，从而理解「增反减同」到底在比什么。
3. 作为学生，我想看到磁铁到达最近点的瞬间：磁通最大、电动势为零。
4. 作为学生，我想切换磁极朝向，确认感应电流的绕向会整体反过来。
5. 作为学生，我想拖动匝数和电阻，验证 ε ∝ N、I = ε/R。

## 4. 物理模型

条形磁铁用**磁偶极子**近似，沿线圈轴线（x 轴）按余弦规律往复运动：
`X(t) = x_c + A·cos(ωt)`，`ω = 2π/T`。线圈是 N 匝、半径 `a` 的圆环，
位于 y-z 平面，法向 `n̂ = +x̂`。

| 量 | 公式 | 备注 |
|---|---|---|
| 单匝磁通 | `Φ₁(x) = μ₀a²(m⃗·n̂) / (2(a²+x²)^{3/2})` | 由 `A⃗ = μ₀/(4π)·(m⃗×r̂)/r²` 环积分得到 |
| 磁通匝链数 | `Ψ = N·Φ₁` | |
| 感应电动势 | `ε = −N·dΦ₁/dt = (3/2)Nμ₀a²(m⃗·n̂)xẋ / (a²+x²)^{5/2}` | **负号即楞次定律** |
| 感应电流 | `I = ε/R` | |
| 感应磁场 | `B' = μ₀NI/(2a)` | 沿法向 |
| 阻力 | `F = N·I·dΦ₁/dx` | 恒与 `ẋ` 反向 |

**楞次定律不需要额外规则**：它完全包含在法拉第定律的负号里。
可作定量验证：`F·ẋ = −I²R ≤ 0`，即机械功全部转化为焦耳热。

**符号约定**：磁矩由 S 极指向 N 极。N 极正对线圈时 `m⃗·n̂ < 0`，
故穿过线圈的磁通为负；靠近时其绝对值增大，`dΦ/dt < 0`，于是 `ε > 0`。

**参数边界**：`N ≥ 1`、`R ≥ 0.1 Ω`、`m ≥ 0.1 A·m²`、行程 `≥ 2 cm`、`T ≥ 0.5 s`。

## 5. 需求与验收

### REQ-IND-001 · 磁通量闭式解正确
`Φ₁(x)` 必须等于 `∮A⃗·dl⃗` 的数值积分。

验收：4000 段数值环积分与闭式解相对误差 < 1e-4。

### REQ-IND-002 · 电动势 = 磁通变化率的负值
验收：解析 `dΦ₁/dx·ẋ` 与 `Φ₁` 的有限差分一致（相对误差 < 1e-4）。

### REQ-IND-003 · 楞次定律：ε 与 dΦ/dt 反号
验收：扫描 61 个时刻，`ε·dΦ/dt ≤ 0` 恒成立。

### REQ-IND-004 · 靠近排斥、远离吸引
验收：扫描 60 个时刻，`F·ẋ ≤ 0` 恒成立；磁铁过最近点后 `F` 反向。

### REQ-IND-005 · 最近点：磁通最大、电动势为零
验收：`|ε(T/2)| < 1e-12`，且 `|Φ₁(X(T/2))|` 为全程最大（相对误差 < 1e-9）。

### REQ-IND-006 · 换向：靠近与远离的电动势异号
验收：`ε(0.25T)·ε(0.75T) < 0`。

### REQ-IND-007 · 感应磁场反对磁通变化
验收：扫描 60 个时刻，`B'·dΦ/dt < 0`（在 `|dΦ/dt| > 1e-12` 处）。

### REQ-IND-008 · 能量账：F·v = −I²R
验收：扫描 60 个时刻，相对误差 < 1e-9。

### REQ-IND-009 · 电流绕向与右手定则一致
验收：N 极靠近时 `ε > 0`、`B' > 0`、`currentSense(ε) = −1`。

### REQ-IND-010 · 匝数正比与电阻反比
验收：`ε ∝ N`（N 加倍 → ε 加倍）；`I ∝ 1/R`。

### REQ-IND-011 · 讲解脚本
≥ 8 步，覆盖「原磁场 → 增反 → 宏观排斥 → 最近点误区 → 减同 → 吸引 → 换磁极 → 匝数」。

验收：末步 `pause: true`，至少 1 次模式切换。

### REQ-IND-012 · 内容配额
`formulas ≥ 3`、`pitfalls ≥ 3`、`quiz ≥ 3`、`assumptions ≥ 4`。

## 9. 开发过程中抓到的真 bug

1. **电流绕向的正负号**：最初直接让电流沿圆环参数化的正方向（`ringTangent`）流动。
   但把 `r(θ) = (0, a sinθ, a cosθ)` 代进 `∮dl⃗ × r⃗` 算出来是 **−x̂**，
   也就是说这个方向与法向 `+x̂` 是**左手**关系。ε > 0 时电流必须走**反向**。
   这个错误极其隐蔽——箭头照常转，肉眼分辨不出转向反了，只有把两次右手定则
   都算出来才会发现。修正方式是显式写 `currentSense(ε) = −sign(ε)`，
   并加一条测试锁死：N 极靠近 → ε > 0 → `sense = −1`。
2. **磁极切换时颜色不跟着换**：初版把近端固定画成红色（N）。切到 S 极正对线圈后，
   近端应该是蓝色，画面却没变——视觉直接说谎。由于 `box` 图元不支持动态颜色，
   改成在**同一位置放红蓝两个盒子**，用 `ObjectCommon.visible` 绑定
   `nearIsN` / `farIsN` 两个 0/1 标量做互斥显隐。
3. **磁铁会穿过线圈中心**：行程滑块拉到 28 cm 时，若最近点仍按 0.16 m 算，
   磁铁中心会跑到 0.16 − 0.14 = 0.02 m，几乎贴到线圈平面，
   此时偶极近似完全失效。处理办法是让最近点**固定**为 0.16 m，
   行程只改变最远点，并加一条测试断言「磁铁中心全程 > 磁铁半长」。
4. **线圈中心的光晕在近距离相机下爆成一团白**：为让磁铁/线圈看得清，
   相机从 `[0.95, 0.72, 1.15]` 拉到 `[0.42, 0.30, 0.46]`。拉近后画面正中
   出现一块 60×40 px 的纯白区域（通道全 > 248），青色 `#22d3ee` 被冲没。
   排查分两步：
   * 先怀疑 `coil-center` 粒子——它带一个 `scale = r × 7` 的 **AdditiveBlending**
     光晕 sprite，`r = 0.016` 时光晕半径 0.112 m，是线圈半径 0.1 m 的 1.1 倍，
     等于在矢量原点糊了一团光。改成 `glow: false` + `radius: 0.012` 后
     过曝**没有消失**（1410 → 1902，反而变大），说明它不是主因。
   * 改用时间轴 scrub 做对照：暂停后逐点扫描 t = 0…72，发现过曝只在
     **个别帧**出现——t = 4 与 t = 16 的磁铁位置、速度完全相同
     （x = 20.00 cm、v = −14.51 cm/s），一个爆一个不爆。
     这种"同状态不同结果"只能是**渲染瞬态**，与物理无关：
     磁铁盒 `metalness 0.55` 叠着组件里**硬编码的 `clearcoat: 0.4`**，
     清漆的镜面高光随磁铁移动扫过相机，正好正对时被 bloom 放大成白团。
   修法是给 `box` 图元补两个可选字段 `clearcoat` / `envMapIntensity`
   （默认值 0.4 / 1.1 保持不变，其余 11 个场景零影响），
   磁铁盒显式设成 `clearcoat: 0.06, envMapIntensity: 0.35`。
   复测 t = 0…72 共 12 帧：**最大单帧过曝 0，全程累计 0**。

   > 教训：材质参数是**相机距离的隐函数**。拉近相机时物体在屏幕上变大，
   > 单位面积上的镜面高光能量并不变，但 bloom 是按屏幕尺度做的，
   > 所以"拉近"会实质性地放大过曝。以后凡是调 `camera.position`，
   > 都要顺手复测过曝像素数，不能只看构图。
